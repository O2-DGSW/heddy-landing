# 이미 본 모션은 결과로 남기기 (이슈 #89)

## 왜

끝까지 내린 뒤 다시 올리면 각 섹션 모션이 거꾸로 재생됐다. 고정 구간(떠나기)이 역재생으로 수 초씩 걸리기도 했다. 다시 내려가도 같은 모션을 처음부터 다시 봐야 했다. 한 번 본 장면은 완성된 결과 그대로 화면만 이동하게 한다.

## 설계

- **본 위치**: 지금까지 내려간 가장 아래 위치 `seenScrollY`다. 올라가도 줄지 않는다.
  - `ScrollSceneProvider`가 프레임마다 `noteSeenScrollY`로 기록한다.
  - 보간 그룹(`sceneDispatcher`)은 자기가 보간해 지나온 위치만 따로 기억한다. 그래서 처음 내려갈 때 실제 위치로 건너뛰지 않는다.
- **섹션 모션 위치 `frame.sceneY(key)`**: 섹션이 화면에 보이면 본 위치를, 아직 화면 아래면 지금 위치를 쓴다.
  - `progress(key)`가 이 값을 쓴다. 섹션 카피·패널·폰 화면 속 진행이 결과로 남는다.
  - 리포트 막대와 record 스핀도 `sceneY`로 바꿨다.
  - 화면 아래 섹션을 제외하는 이유: 그 섹션을 완성으로 계산하면 고정 폰 레이어가 앞 섹션 자리에서 엉뚱한 자세를 잡기 때문이다.
- **고정 폰 레이어의 자세·화면 선택은 실제 위치를 그대로 따른다**: 섹션 사이 이동 중 폰이 페이지와 함께 움직이는 것은 화면 이동 자체라서다. 대신 화면 안 진행은 결과 상태다.
- **전환 시간표**: `fullpagePlan(from, to, sections, H, seenScrollY)`에서 본 위치까지의 sticky 구간은 `seen` 종류로 0초 처리한다.
  - 다시 올라가기와 다시 내려오기 모두 0.9초 화면 이동만 한다.
  - 본 위치가 sticky 구간 중간이면 거기서 잘라, 남은 부분만 처음처럼 재생한다.
- **헤더 로고·점 내비 다크 판정**: `ar.top` 이전에는 아니다. AR을 다시 내려올 때 다크 패널이 결과로 남아 있어도, 섹션이 아직 화면 위쪽에 닿지 않았으면 헤더 로고를 숨기지 않는다.

## 결과 (1512×862, 로컬 개발 서버)

| 이동          | 이전                            | 이후                         |
| ------------- | ------------------------------- | ---------------------------- |
| 처음 내려가기 | 장면별 도착 모션                | 그대로(변경 없음)            |
| 다시 올라가기 | 떠나기 역재생 + 0.9초 이동      | 0.9초 이동만, 결과 화면 유지 |
| 다시 내려가기 | 도착 모션 다시 재생(최대 수 초) | 0.9초 이동만, 결과 화면 유지 |

- 올라갈 때 확인한 결과 상태: 공유(QR 모달·웹뷰), AR 다크 패널, 리포트 막대, 시술 기록 목록.
- 다시 내려갈 때 record 폰은 스핀 없이 정면으로 들어온다.

## 남은 점

- 본 위치는 새로고침하면 처음부터 다시 쌓인다(저장하지 않음).
- 창 크기가 바뀌면 본 위치(px)가 섹션 경계와 조금 어긋날 수 있다.
