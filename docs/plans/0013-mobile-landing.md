# 모바일 랜딩 배치와 성능

## 왜

명함 QR이 랜딩으로 오면서(이슈 #48) 모바일 방문이 늘어난다. 데스크톱과 같은 흐름을 유지하면서 모바일을 다듬는다. 이슈 #50.

기존 문제(iPhone 13, 390×664):

- 폰이 작고(화면 높이 39%) 화면 70% 지점에 있어 카피와 폰 사이가 비었다.
- 기록 섹션 큰 날짜, 리포트 섹션 지표 막대가 폰과 겹쳤다.
- 공유 섹션 폰 두 대가 아래에 작게 몰렸다.
- 3D 캔버스를 화면 밖까지 3배 해상도로 그렸다.

## 참고한 사례

- The Pudding, [Responsive scrollytelling best practices](https://pudding.cool/process/responsive-scrollytelling/)
  - 의미 있는 전환은 모바일에서도 스크롤을 유지한다.
  - vh 대신 고정 높이를 쓴다(주소창이 접히고 펴지며 바뀜).
  - 무거운 연출은 줄인다.
- [토스 홈페이지](https://toss.im/) 모바일: 한 열, 앱 화면을 화면 폭 대부분 크기로.
- [Apple AirPods Pro](https://www.apple.com/kr/airpods-pro/) 모바일: 짧은 헤드라인 + 화면을 채우는 큰 제품 이미지. 폰 목업도 폭 60~70%.

## 결정

- **폰 확대(`MOBILE_ZOOM`)**
  - 모바일 기본 크기(S)는 히어로 3D V자 두 대(씬 폭 ≈ 924)가 화면 폭에 들어오는 크기다. `scaleWidthDivisor` 620 → 960.
  - 합체가 끝나면(archive .86~1) 남는 공간을 채울 만큼 키운다(높이 56%·폭 62% 이내).
  - 공유에서 두 대가 나란히 서면 각 0.44W로 줄인다(A 0.27W · B 0.73W).
  - 마지막 섹션에서 다시 키운다.
  - 3D는 묶음 배율(RecordRig · ShareRigB)과 화면 오버레이 배율로 같은 크기를 낸다. 캔버스 크기는 그대로라 무거운 리사이즈가 없다.
- 폰 중심을 0.7H → 0.66H, 카피 시작을 14vh → 10svh로 옮긴다.
- **주소창 대응**
  - 터치 기기에서 폭이 같고 높이 변화가 150px 이하면 이전 높이를 쓴다(`stableViewportSize`).
  - 고정 섹션은 `h-svh`, 모바일 포스터 CSS도 svh.
- **3D 캔버스**
  - 모바일은 화면 폭만 그린다. 세로 시야각이 고정이라 같은 자리·크기로 그려진다.
  - 해상도는 항상 2배다. DPR 3 폰은 낮추고, DPR 1 모니터는 올린다.
- **겹침**
  - 기록 큰 날짜는 모바일에서 40px.
  - 리포트 지표 막대는 모바일에서 숨긴다. 폰 화면 안 같은 막대가 같은 타이밍으로 찬다.
  - 추천 카드는 화면 오른쪽 끝 8px 안쪽까지만 나온다.
