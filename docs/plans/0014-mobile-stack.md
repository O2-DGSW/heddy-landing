# 모바일 전용 랜딩: 토스식 쌓기 구성

## 왜

모바일에서 고정 3D 폰이 스크롤에 맞춰 움직이는 방식은 무겁다(사용자 피드백). 이 방식은 0013에서 크기·배치만 다듬었다. toss.im 모바일처럼 섹션을 쌓고 가벼운 등장 효과만 쓰는 모바일 전용 랜딩으로 바꾼다. 이슈 #52.

참고: [toss.im](https://toss.im/) 모바일(iPhone 13 크기로 직접 스크롤해 확인)

- 고정 요소는 헤더 하나다. 섹션이 위에서 아래로 쌓인다.
- 기능 하나 = 회색 둥근 카드 안 앱 화면 + 굵은 제목 + 회색 설명.
- 스크롤마다 움직이는 3D·폰이 없다.

## 결정

- **폭 1024px 미만(`lg` 미만) = 모바일**
  - 데스크톱 섹션·3D 폰 레이어는 CSS로 숨긴다.
  - 3D(Spline)·폰 화면 이미지는 `useMediaQuery`로 데스크톱일 때만 시작한다.
  - 모바일에서 캔버스 0개, Spline 요청 0건을 확인했다.
- **`MobileLanding`**(widgets/mobile-landing)
  - 섹션 순서·문구는 데스크톱과 같다(`SECTION_KEYS`·`COPY.sections`, 명세 테스트).
  - 섹션마다 회색 카드 안 폰 화면 하나. 공유는 폰 두 대, AR은 어두운 톤.
  - 히어로는 데스크톱 포스터와 같은 이미지(같은 sizes라 한 번만 받음).
  - 리포트는 지표 4개를 정지 막대로, 마지막 섹션은 스토어 버튼을 넣는다.
- **화면 이미지**(`public/screens/mobile/`)
  - 피그마 landing 프레임을 2배로 내보내 webp로 만들었다. 긴 화면은 한 화면 비율로 위쪽만 쓴다.
    - 리포트 964:1921, 추천 964:2081, AR 964:2610, 공유 QR 964:2416, 공유된 기록 980:2940
  - 기록 화면은 데스크톱 기록 화면과 같은 배치로 합성했다(`computeSettledRecordCards`).
- **움직임**: `Reveal`(shared/ui)
  - 화면에 들어오면 한 번, 아래에서 살짝 떠오르며 나타난다(IntersectionObserver + CSS transition, 스크롤 프레임 계산 없음).
  - 첫 화면(히어로)은 처음부터 보인다(LCP).
  - 동작 줄이기면 효과 없음.
