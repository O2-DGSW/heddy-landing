# 첫 진입 직후 스크롤 시 3D 목업 로딩 (이슈 #88)

## 문제

처음 들어와 바로 스크롤하면 3D 목업을 불러오는 과정에서 로딩이 걸린다.

- 배포 사이트, Chrome 1512×862, 진입 1초 뒤 휠: 기록 화면으로 넘어가는 동안 대체용(CSS) 폰이 보이다가 휠 후 약 4초에 3D로 바뀌고, 그때 3D 초기화(116·220·96ms)가 기록 모션과 겹쳐 화면이 멈췄다.
- 준비가 직렬이었다: 유휴 대기(최대 1초) → 폰 레이어 코드 → 런타임 → 씬 파일(736KB) → 압축 해제기(draco) → 초기화.

## 결정

- 첫 화면 직후(유휴 대기 없이) 씬 파일·Spline 런타임·폰 레이어 코드·draco 압축 해제기를 한꺼번에 받기 시작한다(`phone-stage/lib/splinePreload.ts`). 폰 레이어는 유휴 300ms 안에 붙인다(`PHONE_3D.warmupTimeoutMs` 1000 → 300).
- 씬 파일은 캐시 헤더가 없어 따로 받아도 재사용되지 않으므로, 받은 데이터를 `Application.start(buffer)`로 넘긴다(`load(url)` 대신). draco는 1년 캐시라 미리 받으면 런타임 요청이 캐시에서 나온다.
- 3D를 불러오는 중엔 대체용 폰을 숨긴다(`cssPhoneOpacity`). 3D가 준비되면 캔버스가 페이드로 나타난다. 실패·시간 초과·동작 줄이기에서만 대체용 폰.
- 화면이 미끄러지는 동안(0.9초)은 3D 초기화 시작을 미룬다(`isFullpageSliding`, 최대 1.5초).

## 측정 (로컬 프로덕션 빌드, Chrome 1512×862)

| 항목                | 이전                                       | 이후                                                               |
| ------------------- | ------------------------------------------ | ------------------------------------------------------------------ |
| 씬 파일 요청 시작   | 진입 0.86초                                | 0.15초                                                             |
| draco 요청          | 씬 받은 뒤(1.13초)                         | 씬과 동시(0.15초), 런타임 요청은 캐시                              |
| 대체용 폰 → 3D 바뀜 | 있음(배포 사이트에서 휠 후 약 4초)         | 없음(준비 중 숨김)                                                 |
| 진입 0.3초에 휠     | —                                          | 초기화가 화면 이동 뒤(도착 중, 폰 숨김)로 밀려 화면 이동 끊김 없음 |
| 진입 1초에 휠       | 초기화가 화면 이동 중(최대 186ms 멈춤 3회) | 이미 시작된 초기화 1회(270~300ms)                                  |

- 남은 점: 진입 약 1초에 휠을 굴리면 이미 시작된 Spline 초기화(내부에서 쪼갤 수 없음)가 화면 이동과 한 번 겹친다. 실제 네트워크·기기에서 확인이 필요하다.
- `pnpm verify` 325개 통과. 동작 줄이기·모바일은 3D를 받지 않는 기존 동작 유지.
