# 데스크톱 배민식 작은 휠 화면 넘김 (#78)

## 기준과 결정

- 사용자 첨부 영상(2026-10-16 18:09:59)과 [배민 사이트](https://www.baemin.com/)의 데스크톱 동작을 확인했다.
- 배민은 1512×982 Chrome에서 1px 휠로 한 화면 높이만큼 이동하고 약 1.2초에 멈췄다. 헤디는 기존 요청의 느긋한 움직임을 반영해 1.8초로 전환한다.
- 기존 가상 스크롤 길이 비례 2.2~5.2초 대신 `FULLPAGE.durationMs=1800`으로 통일한다. 실제 scrollY를 움직여 3D와 각 섹션 모션은 보존한다.
- 휠 양에 임계값을 두지 않고 1px·소수점 입력도 받는다. 애니메이션 중 입력은 예약하지 않고 360ms 미만으로 이어지는 관성은 한 제스처로 소비한다.
- 데스크톱 휠을 캡처 단계에서 처리한다. scrollY가 조금 달라졌다는 이유만으로 중단하지 않고, 포인터·터치·리사이즈처럼 명시적인 조작으로 중단한다.
- 모바일 자유 스크롤, 팝오버·내부 스크롤의 기본 조작, 동작 줄이기에서 즉시 이동은 유지한다.

- [x] 양방향·긴 관성 입력·이동 중 스크롤 보정 검증

## 결과

- `pnpm verify`: 타입·린트·FSD 및 33개 테스트 파일의 300개 테스트 통과. `pnpm build`와 변경 파일 포맷·`git diff --check` 통과.
- Chrome 1512×982: 실제 1px 휠로 record 완성 화면 도착, 850ms 시점에는 여전히 전환 중임을 확인했다. -1px로 인트로 복귀.
- 0.1px 관성 입력을 3.3초간 이어도 한 섹션만 이동. 전환 중 scrollY를 37px 보정해도 목표까지 완료.
- 포인터로 직접 조작하면 중단하며, dialog 내부 휠은 그 안에서만 스크롤된다. Home/End와 상하단 경계 보존.
- 390×844 모바일은 작은 자유 스크롤(160px 입력 후 92px 이동)을 유지한다. 동작 줄이기에서는 1px 입력으로 즉시 다음 화면에 도착한다.
- 브라우저 런타임 오류 0건. 결과·캡처는 로컬 `.snapshots/desktop-wheel/`에 저장했다.
- 물리 마우스/트랙패드 및 Safari/Firefox는 별도 미실행이다. 영상·레퍼런스 확인과 로컬 Chrome 자동화 검증을 수행했다.
