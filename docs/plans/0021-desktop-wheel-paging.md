# 데스크톱 배민식 작은 휠 화면 넘김 (#78)

## 기준과 결정

- 사용자 첨부 영상(2026-10-16 18:09:59)과 [배민 사이트](https://www.baemin.com/)의 데스크톱 동작을 확인했다.
- 배민은 1512×982 Chrome에서 1px 휠로 한 화면 높이만큼 이동하고 약 1.2초에 멈췄다. 헤디는 한 입력에 한 섹션 이동하는 조작만 참고하고, 중간 모션을 충분히 보여 달라는 #80 후속 요청에 따라 더 천천히 전환한다.
- 기존 가상 스크롤 길이 비례 2.2~5.2초 대신 일정한 전환으로 통일한다. 최초 1.8초에서 #80 후속 피드백에 따라 5초로 늘려 중간 모션을 볼 시간을 확보했다. 실제 scrollY를 움직여 3D와 각 섹션 모션은 보존한다.
- 휠 양에 임계값을 두지 않고 1px·소수점 입력도 받는다. 애니메이션 중 입력은 예약하지 않고 360ms 미만으로 이어지는 관성은 한 제스처로 소비한다.
- 데스크톱 휠을 캡처 단계에서 처리한다. scrollY가 조금 달라졌다는 이유만으로 중단하지 않고, 포인터·터치·리사이즈처럼 명시적인 조작으로 중단한다.
- 모바일 자유 스크롤, 팝오버·내부 스크롤의 기본 조작, 동작 줄이기에서 즉시 이동은 유지한다.

## 결과

### #80 느린 전환 후속 조정

- 5초 전환으로 늘렸다. `pnpm verify`(300개 테스트)와 프로덕션 빌드 통과.
- 추가 피드백: `01` 등 섹션 번호를 제거했다. 중간에 확 끌려가는 느낌을 줄이기 위해 5초는 유지하고 easeInOutCubic을 easeInOutSine으로 바꿨다. 공통 섹션 문구에는 기존 Reveal의 700ms 페이드·이동 모션을 연결했다.
- 추가 검증: `pnpm verify` 301개 테스트와 빌드 통과. Chrome에서 번호 없는 5개 기능 이름, 1초 시점 약 9.5% 이동, 문구의 실제 중간 불투명도와 완료 상태, 모바일 기능 이름을 확인했다. 런타임 오류 0건. `.snapshots/slow-motion/gentle-results.json`에 기록했다.
- Chrome 1512×982에서 1px 휠 입력 후 1.8초에는 여전히 이동 중이고 중간 기록 쌓임을 지나 목표 화면에 도착했다. 관성 입력을 이어도 한 섹션에서만 정지한다.
- 동작 줄이기에서는 즉시 이동을 유지한다. 브라우저 런타임 오류 0건. 중간·완료 캡처는 로컬 `.snapshots/slow-motion/`에 저장했다.
