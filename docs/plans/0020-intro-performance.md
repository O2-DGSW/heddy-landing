# 인트로 반복 재생과 초기 로딩 개선 (#76)

## 범위

- 장면 밖에서 자식 SVG의 visibility가 부모 숨김을 덮는 잔상 수정.
- 인트로는 현재·다음 장면만 마운트하고 후속 장면 코드는 분리한다.
- 숨겨진 3D 포스터 미리 받기 제거, 기록 섹션 접근 시 3D 준비.
- AR을 포함해 한 입력에 한 섹션 이동. 2.2~5.2초 전환과 관성 꼬리 소비 유지.
- 인트로 하단 그림자와 스크롤 안내 버튼. 모바일 자유 스크롤·동작 줄이기 보존.

## 구현과 검증 결과

- `visibility`만 숨기면 자식 SVG의 명시적 `visible`이 부모를 덮는다. 장면 루트에 `display:none`을 적용하고 지나간 장면은 언마운트한다.
- 첫 문구는 서버 HTML에 완성 상태로 표시한다. 첫 방문은 2.4초부터 시작하고 이후 45초 반복은 0초부터 원래 타이핑을 유지한다.
- 현재·다음 장면 최대 두 개만 마운트하고 Records/Features/Ending 코드를 분리한다. 늦게 마운트된 구독자는 현재 시각·스크롤 프레임을 즉시 받는다.
- 기존 전체 레이어의 `will-change`를 제거하고 화면 밖·백그라운드 탭에서는 재생과 오디오를 함께 일시정지한다.
- 3D 모듈과 폰 화면은 record 시작 한 화면 전부터 준비한다. 인트로에서 쓰이지 않는 옛 3D 포스터와 우선 요청을 제거한다. 동작 줄이기에서는 CSS 폰을 사용한다.
- 1512×982 Chrome에서 실제 91초 재생: 물결 등장 2회, 반복 경계 2회, 장면 밖 잔상 0회, 마운트된 장면 최대 2개.
- 휠+5.2초 연속 관성 입력에도 record에서 한 번만 정지. 1초 후에는 이동 중임을 확인했다. PageDown으로 AR 포함 각 섹션에 한 번 정지한다.
- 실제 Spline 캔버스와 record 폰 배치를 확인했다. 안내 버튼·오디오 화면 밖 정지/복귀·390×844 모바일·동작 줄이기 검증 통과. 런타임 오류 0건.
- 최종 빌드에서 Spline 씬 다운로드를 차단한 뒤에도 CSS 폰이 표시되는 것을 확인했다. 최종 안내 화면과 폴백 캡처도 저장했다.
- `pnpm verify`: 33개 파일, 299개 테스트 통과. `pnpm build` 통과.
- 캡처와 브라우저 결과: 로컬 `.snapshots/intro-performance/`.

## Lighthouse 비교

Lighthouse 13.5.0, 로컬 프로덕션 빌드, Chrome, 기본 시뮬레이션과 새 프로필. 데스크톱은 desktop preset, 모바일은 기본 preset. 각 표의 수치는 1회 측정이며 외부 글꼴/CDN·로컬 실행 환경의 편차가 있다. 실사용 기기나 배포 사이트의 점수를 보장하지 않는다.

| 지표               | 전     | 후     |
| ------------------ | ------ | ------ |
| 데스크톱 성능      | 89     | 99     |
| 데스크톱 LCP       | 2.15초 | 0.75초 |
| 데스크톱 초기 요청 | 87     | 27     |
| 모바일 성능        | 98     | 99     |
| 모바일 LCP         | 1.80초 | 2.23초 |
| 모바일 TBT         | 131ms  | 40ms   |
| 모바일 초기 요청   | 87     | 33     |

모바일 LCP 대상은 서버 렌더되는 상단 제목이며 외부 Pretendard 교체 렌더링의 영향을 받는다. 이 측정에서는 모바일 LCP 개선을 확인하지 못했다. 영상·3D 초기 요청과 차단 시간은 줄었지만, 모바일 LCP는 배포 환경에서 별도 확인이 필요하다.

## 유지 범위와 참고

- Spline 원본·런타임 의존성·화면 품질은 유지한다. 실제 Safari/Firefox와 물리 기기 터치 검증은 미실행이다.
- [LCP 최적화 지침](https://web.dev/articles/optimize-lcp): 첫 화면 콘텐츠의 렌더 지연을 줄이고 화면 밖 리소스와 경쟁하지 않게 한다.
- [Next.js 지연 로딩](https://nextjs.org/docs/app/guides/lazy-loading): Client Component 경계 안에서 필요한 시점에 코드를 불러온다.
